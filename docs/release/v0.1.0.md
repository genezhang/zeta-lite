# zeta-lite v0.1.0

**An in-browser SQL database** — a WebAssembly build of the Zeta database engine
that runs entirely client-side. This is the **v0.1 public preview**: free to use,
including commercially; not open source (the engine source is closed and available
separately under NDA).

## What it is

A ~2.87 MB (gzipped) WebAssembly artifact that compiles the same parser, planner,
optimizer, and executor as the Zeta server down to a browser tab — no server, no
network, no install. Its defining feature is a **log-centric asynchronous MVCC
core**, which gives it two capabilities no other in-browser SQL engine offers:

- **Overlapping snapshot-isolated transactions on a single thread** — multiple
  transactions open at once, each on its own snapshot, with SI write-write
  conflict detection, and no threads or `SharedArrayBuffer`.
- **Copy-on-write database branching** — whole-database fork / merge / rebase,
  as a fork timestamp over the MVCC log.

On top of these it carries a feature-complete PostgreSQL surface (joins, CTEs,
window functions, JSONB + GIN, full-text search, HNSW vector search, SQL/PGQ
graph queries, multi-database) and snapshot-to-OPFS persistence that needs no
worker, no `SharedArrayBuffer`, and no cross-origin-isolation headers.

Loose web-target files with a checksum manifest:

|---|---|
| `zeta_wasm.js` | wasm-bindgen `--target web` JS glue (self-initializing module) |
| `zeta_wasm_bg.wasm` | the compiled engine |
| `zeta_wasm.d.ts`, `zeta_wasm_bg.wasm.d.ts` | TypeScript types |
| `THIRD-PARTY-NOTICES.txt` | third-party license notices (ship with the wasm) |

| `SHA256SUMS` | integrity manifest over all of the above |

## Install

```bash
# From a checkout of github.com/genezhang/zeta-lite:
./scripts/fetch-artifact.sh v0.1.0     # downloads assets, verifies SHA256SUMS
python3 -m http.server -d playground 8080
#   → open http://localhost:8080
```

`fetch-artifact.sh` verifies every downloaded file against `SHA256SUMS` and fails
closed on any mismatch. There is no npm package yet — an `npm install zeta-lite`
distribution is planned for a later release.

## Known boundaries (v0.1)

- Concurrency is transaction-lifetime overlap between statements, not
  sub-statement in-query parallelism (single thread).
- Durability is snapshot-based (OPFS), not per-commit fsync.
- `exportSnapshot()` does not yet serialize branches — merge or drop branches
  before persisting.
- No OLAP/columnar engine — this is the row-oriented OLTP form factor.
- `embed()` ships no bundled model — register a synchronous embedder from
  JavaScript (`setEmbedFn`) or bind precomputed vectors.

See the repository README and `docs/sql_reference.md` for the full surface, and
`docs/paper/` for the technical report.
